# 染缸预约台（打样排期）

替代"白板 + 微信催单"的染缸占位系统：批次登记后按染缸与开始时刻占位，自动校验机器重叠；
色差目标未定、配方未复核的批次留在待排；加急可提前、开染后排期锁定不可打乱；
配方/保温/后整理/染程变更自动退回待确认并保留旧排期与原因；可查看空档、交期风险与完整调整历史。

## 业务规则

- **占位冲突**：同一染缸时间区间重叠即冲突。`开染` / `完成` 批次是锚点，任何操作（手动、自动、加急、确认）都不能移动它们。
- **待排三条件**：色差目标未定、配方未复核、期望缸时与现有安排重叠 → 留待排并逐条标注原因；阻碍消失后自动重算。
- **自动排程**：加急优先 → 交期先后 → 登记先后，只把批次放入空档。
- **加急提前**：窗口内无空档时，可把**普通已排**批次挤回待排（记录原因）；加急单、开染/完成批次受保护。
- **变更冻结**：已排/待确认批次修改配方、保温时间、后整理、染程时长 → 退回`待确认`，旧排期在时间轴上冻结显示并记录原因；确认时若旧排期已冲突，必须退回待排重排。
- **交期风险**：已逾期 / 高风险（缓冲不足）/ 预警（临近交期）/ 正常 / 无排期。

## 分层结构（各自维护、互不耦合）

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 排程规则（纯函数引擎） | `src/domain/` | 类型、冲突判定、空档、自动排程、手动占位、加急挤退、变更检测、交期风险。无 React、无存储，可独立测试 |
| 批次档案 | `src/data/store.ts` | localStorage 持久化 + 演示种子数据（批次、染缸、规则、历史） |
| 页面 | `src/pages/` `src/components/` | 排程看板（甘特）、批次档案、染缸空档、调整历史、排程规则 |
| 应用编排 | `src/state/ReservationContext.tsx` | 串联引擎与档案、记录调整历史、操作反馈 |

页面：

1. **排程看板**：按天的染缸甘特图（开染/已排/待确认/完成/空档、当前时刻线、加急标记），一键自动排程，交期风险清单。
2. **批次档案**：批次登记与编辑（订单、面料、色差目标、配方与复核状态、保温、后整理、染程、交期、加急、期望缸时），按状态/关键字/加急筛选。
3. **染缸空档**：按日期、染缸、所需染程时长查询可排空档（仅绕开开染锚点）。
4. **调整历史**：登记、占位、加急提前、退回待确认、确认重排、开染、完成、规则变更等全部留痕，可跳回批次。
5. **排程规则**：时间粒度、排程窗口、风险阈值、加急提前开关、染缸停用/启用维护。

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式），无额外运行时依赖；数据保存在浏览器 localStorage。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62012。构建：`npm run build`，类型检查：`npx tsc --noEmit`。

页面右上"重置演示"可随时恢复内置演示数据。
